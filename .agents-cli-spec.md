# Agent Spec

## Overview

Cloud Summit Concierge is a single ADK agent for conference attendees. It searches a small session catalog, recommends talks based on remembered preferences, and maintains a conflict-free personal agenda. A2UI presents session cards and agenda tables; the public frontend communicates with the deployed agent through the generated FastAPI/A2A surface.

## Example Use Cases

- "Quais sessões de IA generativa existem à tarde?" returns matching catalog entries with time, room, level, and rationale.
- "Adicione as duas melhores à minha agenda" saves compatible sessions and reports any conflict instead of silently overwriting.
- "Lembre que prefiro conteúdo intermediário em português" stores a durable preference for later sessions.
- "Monte uma agenda sobre agentes e segurança" returns a conflict-free itinerary and explains each choice.

## Architecture

- One ADK agent; no sub-agents.
- Deterministic Python function tools own catalog filtering, agenda writes, and conflict detection.
- Firestore is the persistent source for sessions and saved agenda items.
- Memory Bank stores attendee preferences across conversations.
- Vertex AI RAG Engine is limited to session abstracts and event FAQs.
- A2UI formats catalog and agenda responses; the FastAPI frontend remains a thin proxy.

## Tools Required

- `search_sessions`: query Firestore by topic, language, level, and time window using Application Default Credentials.
- `save_session`: add one session to the attendee agenda only when its time range does not overlap another saved session.
- `remove_session`: remove one saved session.
- `get_agenda`: list saved sessions in chronological order.
- RAG retrieval: answer questions grounded in event FAQs and session abstracts.
- Optional image generation: create one shareable agenda card and upload it to Cloud Storage.

## Data Sources & Auth

- Google Cloud project: `emerson-workshops`.
- Runtime region: `us-east1`; global only for models that require it.
- Authentication: local ADC for development and service identities for deployed workloads.
- Firestore collection: a small seeded `sessions` catalog plus attendee agenda data.
- No third-party APIs or API keys.

## Constraints & Safety Rules

- Never invent sessions, speakers, rooms, or times; catalog claims must come from Firestore or RAG sources.
- Never add overlapping sessions; return the conflict and alternatives.
- Treat preferences as recommendations, not eligibility or access guarantees.
- Store only workshop-relevant preferences and agenda selections; do not request sensitive personal data.
- Do not expose credentials, project secrets, internal traces, or raw service errors in the frontend.

## Success Criteria

- Two core evaluation cases pass with response-quality score at or above 0.8.
- Every saved agenda produced in evaluation has zero time overlaps.
- Catalog answers contain only seeded session IDs.
- A local smoke test can search sessions and create an agenda in one conversation.
- The public repository passes the workshop secret scan and uses the `buildwithgemini-` prefix.

- Use the personal Google Cloud project `emerson-workshops`, not a temporary Qwiklabs project.
- Enable Vertex AI and grant only the roles required by the workshop after this spec is approved.
- Use the model already selected by the scaffold; do not replace it unless compatibility requires a documented change.
- Deploy the agent to Agent Runtime and the frontend to Cloud Run only after local tests and evaluations pass.
- Publish publicly as `erbernardino/buildwithgemini-cloud-summit`.

## Future Phases
